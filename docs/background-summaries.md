# Optional PC memory summaries

The selected route is direct Qwen on the paired PC: `qwen3-0.6b-memory` at the authenticated llama.cpp CPU endpoint `http://127.0.0.1:20129/v1/chat/completions`. OmniRoute is unnecessary. Weights are Qwen's official Qwen3-0.6B Q8_0 GGUF, revision `23749fefcc72300e3a2ad315e1317431b06b590a`, SHA-256 `9465e63a22add5354d9bb4b99e90117043c7124007664907259bd16d043bb031` (639,446,688 bytes). The official llama.cpp b11588 Windows CPU ZIP SHA-256 is `f2c1cd95861da57dbe4002f3bdf03c91646f46446cca37cb1219fa31e593cb36`. An explicitly configured legacy OmniRoute route remains supported; the default installer does not install it.

This small model prepares drafts, with GPT checking important facts. It receives only bounded selected source records and returns text. The worker never provides phone tools, shell commands, file paths or model-selected URLs. Source record IDs and versions are added by trusted code. Results are always `proposed`; they cannot change permissions or mark themselves verified.

Phone-side `summary-route.json` selects an existing same-owner PC connection. The PC has an explicit private `summary.json` selecting only the exact loopback URL and model above. Original relay credentials and pairing grants remain unchanged. The model API key is restricted to this model and its one local connection; no external fallback or paid provider is configured.

The optional producer runs outside the main queue loop. It polls an existing PC job ID rather than issuing a new job after a pending result. Durable receipts live in the existing phone/PC journals. A model timeout, offline PC, router rejection or exhausted daily budget produces an unavailable summary result while normal tools and authoritative Tencent memory continue working. Requests are bounded to eight records, 5 KiB of source JSON, 384 output tokens, one local inference slot, a 20-second request timeout and 12 new summaries per day. Thinking is disabled in the inference template; unexpected tool calls and incomplete reasoning output are rejected.

The main phone agent works without a PC. This selected optional background model is hosted on the paired Windows PC and is unavailable when that PC is off. Installing OmniRoute does not itself install a model or grant it device control. Neither OmniRoute nor Qwen weights are installed on the phone. The phone producer pauses at battery 20% or below and resumes above 20%; app mode uses a fresh Android SDK battery observation and root mode reads the system battery capacity.

Installation requires an explicit model choice. Generic plugin installation, silence and a preselected option are not consent. Codex must ask and wait before a future phone-model installation; this release uses a separate optional PC installation. A previously explicit choice applies only to that same installation. The dedicated PC model directory is `%LOCALAPPDATA%/RelayKiteMemory`, with owner-only access; the existing PC worker supervises its controller after Windows sign-in. A missing model does not trigger a download.

For Codex-assisted plugin removal, run `pc_memory_model_remove` on the existing authorized PC link before unlinking. It accepts no paths or commands, validates the recorded dedicated installation and exact process identities, removes its weights/runtime/private router data and leaves original memory and pairing alone. GPT package removal on the phone creates a durable cleanup request, excluding app updates, which waits for the paired PC if offline. Direct plugin removal in ChatGPT settings has no documented device lifecycle event: explicit cleanup is required. Uninstalling the entire phone worker must likewise include cleanup before removing its communication channel.
