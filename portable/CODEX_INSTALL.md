# Установка через Codex — Codaki Portable Use 0.1.4
## Android 0.1.4: несколько дисплеев

До трёх сессий virtual_display, отдельные имена, lease, PID-generation и observations. Один общий UIAutomation inspector обслуживает явно проверенный nonzero display каждого запроса; физический экран не используется как fallback. Ввод сериализован, uncertain блокирует новые действия до проверки. session_stop освобождает только свой дисплей. После перезапуска агент освобождает подтверждённые собственные дисплеи предыдущего процесса; старые session IDs не восстанавливаются. Данные приложений общие; поддержка нескольких activity зависит от приложения.

Ядро можно пересобрать из android/java: `python scripts/build_core.py --r8 /path/to/r8.jar` при JDK8+. Проверяйте core/build-manifest.json, регрессии Java и живые виртуальные экраны. R8 не включён в пакет; сборщик не скачивает зависимости. Для agent с существующим приватным relay включите `--local-ipc` для Mini. При обновлении сохраните конфиг, root-only IPC, журнал и отдельный Android Use.


## Дополнение 0.1.4: Mini Codex и Windows batch

Windows поддерживает batch до 12 шагов с устойчивыми selectors, свежим observation_id и общим timeout до 30000ms. Пакет последовательный; завершённые шаги остаются применёнными, остановленный пакет не возобновляется автоматически. Проверяйте child request IDs; после crash журнал сохраняет completed и inflight_request_id. Для неизвестного исхода требуется проверка реального окна и reconciliation, без повтора ввода.

Чтобы Mini Codex на этом же ПК использовал существующий движок, добавьте --local-ipc-windows к существующей Windows agent-команде после резервной копии и проверки отсутствия активных задач. Опция не создаёт второй engine. HTTP loopback RPC выполняет UI только в исходном потоке агента. Дескриптор в LOCALAPPDATA/CodakiPortableUseIPC/endpoint.json содержит новый локальный секрет с ACL владельца/SYSTEM; его нельзя публиковать или переносить на другой ПК. Mini должен иметь уже одобренную terminal capability. App tokens и облачные grants не меняются.

При обновлении сохраняйте конфиг, журналы и .venv; не заменяйте установленный телефонный runtime в рамках Windows-обновления. Архив 0.1.4 собирается отдельно; предыдущие versioned ZIP не перезаписываются.

Передайте этот файл Codex и поручите установить или обновить Portable Use на вашем Windows-ПК, Android или обоих устройствах. Репозиторий: https://github.com/kalabuxova1-hash/codaki-portable-use

## Проверить пакет

Скачайте `dist/codaki-portable-use-0.1.4-full.zip` и `dist/SHA256SUMS`. Сверьте SHA-256 ZIP до распаковки. Архив содержит исходники, Windows-установщик, облачный сервер, тесты, документацию и Android Magisk ZIP. Дополнительно проверьте `MANIFEST.sha256.json` внутри полного архива. Ключей и конфигураций реальных устройств в пакете нет.

## Windows: новая установка

Нужны Windows 10/11, Python 3.10+ с venv/pip и интерактивная разблокированная сессия. Не устанавливайте root, не меняйте VPN или политики безопасности. Из распакованного каталога:

```powershell
./scripts/install_windows.ps1 -Destination "$env:LOCALAPPDATA\CodakiPortableUse" -Python python
```

Установщик копирует runtime и создаёт виртуальное окружение с pywinauto, Pillow и psutil. Он проверяет Windows backend, но не регистрирует устройство автоматически. При существующем runtime останавливается, чтобы не затереть приватный конфиг.

## Облачная регистрация Windows

1. Откройте существующий сервер владельца через Sites и подтвердите доступ к исходникам. Если сервера нет, создайте собственный закрытый Site по `cloud/README.md`; не выдавайте чужой сервер за свой.
2. Для нового Site скопируйте `cloud/.openai/hosting.json.example` в `hosting.json` и запишите точный выданный Sites project_id. Сохраните D1 binding DB и доступ только владельца.
3. Существующий секрет DEVICE_TOKENS с Android-ключом не заменяйте. Создайте случайный отдельный Windows-ключ (например, `secrets.token_urlsafe(48)` внутри памяти процесса). В Sites задайте WINDOWS_DEVICE_ID (например, windows_MY_PC) и секрет WINDOWS_DEVICE_TOKEN. OWNER_EMAIL и DEVICE_TOKENS нужны для первоначального сервера; их значения в публичный пакет не входят. Разверните обновлённый сервер после изменения окружения.
4. Получите разрешённый Site service access из get_site. Используйте его только для этого Site в OAI-Sites-Authorization; он не заменяет отдельный ключ Windows. Не копируйте телефонную конфигурацию и не меняйте доступ Site на публичный.
5. На самом ПК создайте `agent-windows.json` по примеру. Запишите новый device_id, настоящий relay_url, отдельный agent_token и site_access_token. Вводите ключи через защищённый stdin, не через аргументы команд, чат или Git. Уберите наследование ACL файла, разрешите чтение только владельцу и SYSTEM. Не публикуйте приватный файл.
6. Запустите START_WINDOWS_AGENT.cmd из установленного каталога либо pythonw.exe с `-m portable agent --platform windows --config agent-windows.json --state windows-agent-state` и рабочим каталогом установки; фоновый запуск должен быть скрытым.
7. Проверьте use_devices: ПК должен быть online; use_capabilities должен сообщать parallel_sessions=true, max_sessions=8, input_serialized=true. Проверьте use_apps, старт сеанса, observe и stop. Только после реальных ответов считайте привязку завершённой.

При необходимости включите автозапуск:

```powershell
./scripts/enable_windows_autostart.ps1 -Installation "$env:LOCALAPPDATA\CodakiPortableUse"
```

Задание запускается только в интерактивной сессии текущего владельца, без повышения прав. Не запускайте второй агент параллельно с уже работающим. Если задание существует, сначала прочитайте его параметры; скрипт не заменяет его автоматически.

## Обновление существующего Windows-ПК

Проверьте точный путь установки и командную строку агента. Сохраните исходники в отдельный приватный backup. Остановите только этот агент и его задание. Замените пакет portable из src/portable и shared из src/shared, сохранив agent-windows.json, windows-agent-state и окружение .venv. Обновите зависимости, если изменились requirements-windows.txt. Вновь запустите единственный агент и проверьте реальные capabilities, два разных сеанса и наблюдения каждого. При ошибке остановите обновлённый агент, верните исходники backup и снова запустите. Не удаляйте журнал ради обхода неопределённого действия; сначала прочитайте diagnostics и reconcile с проверенными evidence.

## Параллельные Windows-сеансы

Создавайте до восьми сеансов use_session_start с target, взятым из свежего use_apps. Каждый сеанс привязан к отдельному окну, имеет собственные session_id, observation_id и lease. Одно окно нельзя занять дважды. Закрытие или истечение одного сеанса не закрывает приложения и не завершает другие.

Рабочий стол, учётная запись, клавиатура и мышь общие. Сеансы могут оставаться открытыми одновременно; команды ввода выполняются последовательно. Физическая изоляция дисплеев Windows не предоставляется. Координаты и screenshot требуют выбранного окна на переднем плане; семантический UIA-ввод зависит от возможностей приложения. Не обещайте поддержку свернутых окон: окно с недоступной геометрией возвращает отказ. Не используйте observation одного сеанса в другом. Неопределённый ввод блокирует новый ввод во всех сеансах до проверенного reconciliation.

## Android

Инструкция: [docs/ANDROID_INSTALL.md](docs/ANDROID_INSTALL.md). ZIP `dist/codaki-portable-use-0.1.4-android.zip` содержит оба проверенных JAR. Для виртуальных экранов нужны ранее установленный root/Magisk и подписанный native runtime RelayKite; Termux остаётся только совместимым резервным вариантом. Существующую телефонную установку не меняйте в рамках Windows-установки. Перед Android-обновлением сохраните данные и конфиг, проверьте совместимость, не перезагружайте без согласия владельца.

## Проверки исходников

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
python -m unittest discover -s tests -p 'test_*.py'
node --test cloud/tests/sites.test.mjs
```

Тесты не подменяют реальную проверку устройства. Для Android используйте только выделенный nonzero display; не отправляйте сообщения и не меняйте приватные данные для smoke-проверки.
